BeyondBoard Reproduction Guide

How to install BeyondBoard, run the same sketch on your own computer and in your own AWS account, and repeat every measurement in the paper “BeyondBoard: Cloud Storage, Computing, and Generative AI as One-Line Arduino Calls”. Each evaluation lists the command, the time it takes, and the numbers you should see.

Measured 2026-10-01 to 10-02AWS ap-northeast-1 (Tokyo)License: MIT

Get the code and install the library by copying it into your Arduino libraries folder (from the Library Manager once it is published):

git clone https://github.com/tobitaQ/beyondboard.git
cd beyondboard
cp -r arduino/BeyondBoard ~/Documents/Arduino/libraries/   # then restart the Arduino IDE

2Run with local

local needs no account and no internet. A Python program on your computer talks to the board over USB, keeps data in SQLite, runs the same function files, and asks Ollama.

  1. Prepare the local adapter once.

    python3 -m venv local/.venv
local/.venv/bin/pip install -r local/requirements.txt
ollama pull qwen2.5:3b && ollama pull qwen2.5vl:3b   # only for ask

  2. Open File › Examples › BeyondBoard › 06_LocalAll in the Arduino IDE and upload it. Close the Serial Monitor: the adapter needs the port.

  3. Start the adapter. It finds the board when only one is connected and shows everything the sketch prints.

    local/.venv/bin/python local/cloud_local.py
Expected

The sketch's lines appear in the adapter's output: a saved value, the function's answer, and the AI's answer. python3 local/cloud_local.py stats shows how often each call ran.

3Run with aws

The backend is built in your own AWS account with one command. Preparation is needed once per computer.

  1. Install Node.js and the AWS CLI. Create an access key for your IAM user in the AWS console and enter it.

    aws configure                 # region: ap-northeast-1 (or edit backend/settings.json)

  2. Install the backend's packages and bootstrap the CDK (once per account and region).

    cd backend
npm install
npx cdk bootstrap

  3. Build the backend. This creates the Lambda function URL, the DynamoDB table, the S3 bucket, one Lambda per user function, and a token per device listed in settings.json.

    npm run deploy                # 1–2 minutes after changes; seconds when nothing changed

  4. Open backend/out/device-1/aws_config.h, write your Wi-Fi name and password (the 2.4 GHz network), and copy the file into the sketch folder of the example you want to run.

  5. If the AWS console asks for it, submit the one-time use-case form for Anthropic models on Amazon Bedrock.

Keep this file private

aws_config.h holds the device's token and your Wi-Fi password. It is ignored by Git. If it leaks, run npm run revoke -- device-1 to stop the token, or npm run rotate -- device-1 to make a new one.

Check the backend from the computer, exactly as a device would call it:

npm run call -- save temp.csv 23.5
npm run call -- load temp.csv
npm run call -- run detectAnomaly 38.2
npm run call -- ask "Is this hot?" 38.2

4Examples 01–07

Board settings: ESP32 Dev Module with upload speed 115200. For the ESP32-S3 camera board: PSRAM “OPI PSRAM”, flash 16 MB, partition “16M Flash (3MB APP/9.9MB FATFS)”. From the command line:

CLI="/Applications/Arduino IDE.app/Contents/Resources/app/lib/backend/resources/arduino-cli"
"$CLI" compile --fqbn esp32:esp32:esp32:UploadSpeed=115200 --library arduino/BeyondBoard --upload --port <PORT> <SKETCH_DIR>
"$CLI" compile --fqbn esp32:esp32:esp32s3:PSRAM=opi,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB --library arduino/BeyondBoard --upload --port <PORT> <SKETCH_DIR>

5Reproduce the evaluation

Each block names the paper's table, the command, and what you should get. Scripts that only read committed result files run in seconds; experiments on the board take minutes.

Computed from the sketches and cloud code in evaluation/baselines/ and arduino/BeyondBoard/examples/; no judgment involved.

Steps, concepts, and the second rater Tables 8, 9, 11

Image tasks: on the board vs. through BeyondBoard Table 12

The protocol in evaluation/e8_images/PROTOCOL.md was fixed before any detector ran. The images are not in the repository (WIDER FACE is CC BY-NC-ND 4.0); the scripts rebuild the same 50.

  1. Download the WIDER FACE validation set and annotations from the official release (CUHK-CSE/wider_face on Hugging Face: WIDER_val.zip, wider_face_split.zip) and the COCO 2017 annotations (annotations_trainval2017.zip). Unpack them.

  2. Select and encode the images, then embed them in a header.

    cd evaluation/e8_images
python3 select_images.py WIDER_DIR OUT --coco COCO_DIR/annotations/instances_val2017.json
python3 make_header.py OUT/images OUT/images.h   # copy images.h into each sketch folder

    OUT/selection.csv must match the committed selection.csv.

  3. On-device arm: install arduino-esp32 2.0.14 into a separate folder (3.x no longer ships esp-dl), upload OnDeviceFaces to the ESP32-S3, and record three passes.

    export ARDUINO_DIRECTORIES_DATA=$HOME/esp32-2.0.14 ARDUINO_BOARD_MANAGER_ADDITIONAL_URLS=https://espressif.github.io/arduino-esp32/package_esp32_index.json
"$CLI" core update-index && "$CLI" core install esp32:esp32@2.0.14
"$CLI" compile --fqbn esp32:esp32:esp32s3:PSRAM=opi,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB --upload --port <PORT> OnDeviceFaces
unset ARDUINO_DIRECTORIES_DATA
../../local/.venv/bin/python capture.py <PORT> results/ondevice 3

  4. Cloud arm: faceBoxes must be in backend/settings.json and deployed. Copy aws_config.h into CloudFaces, upload with core 3.3.5, and record three passes (about 2 minutes each; about USD 0.40 of Rekognition in total).

    ../../local/.venv/bin/python capture.py <PORT> results/cloud 3 1200

  5. Optional: upload LocalDescribe, start Ollama, and run local/cloud_local.py to describe the same ten images offline.

  6. Score both arms.

    python3 analyze.py                      # needs scipy

Errors under injected faults Table 13

The sketch evaluation/e9_faults/FaultTable causes eleven faults on the ESP32-S3. The testFail function must be deployed.

cd evaluation/e9_faults
../../local/.venv/bin/python run_faults.py <PORT> device-1 results/faults.txt
cd ../../backend && npm run rotate -- device-1   # the run revokes the token; make a new one
This run revokes your device token

At “WAITING” the script runs npm run revoke to test the AUTH error. Afterwards, run npm run rotate and copy the new aws_config.h into your sketches. Your Wi-Fi name is masked in the saved results.

Expected

Ten faults produce a sentence that names the cause; the Wi-Fi drop reconnects and saves exactly one line.

Latency and concurrency Tables 14, 15

Upload benchmarks/LatencyBench (with aws_config.h; set USE_LOCAL 1 for local), save its CSV output under benchmarks/results/, then summarize. Concurrency runs from the computer.

python3 benchmarks/concurrency.py aws
local/.venv/bin/python local/cloud_local.py --no-serial --http 8787   # prints a token; or set CLOUD_LOCAL_TOKEN
python3 benchmarks/concurrency.py local http://localhost:8787 <TOKEN>
python3 benchmarks/summarize.py           # p95 = 29th of 30 sorted values
Expected (medians)

aws: save 67, load 107, run 207, ask with choices 618 ms. local: 25, 28, 42, 121 ms. Wi-Fi congestion moves the p95 of aws save the most.

6When something fails

SymptomCause and fix
Wi-Fi “… was not found”ESP32 only uses 2.4 GHz. If the router shows two names (…-G-… and …-A-…), use the 2.4 GHz one.
Upload fails on the ESP32Set the upload speed to 115200; 921600 failed with our board.
Camera does not startEnable PSRAM (OPI on ESP32-S3) and check the board name in camera.begin().
“This device is not registered”The token was revoked or aws_config.h is old. Run npm run rotate -- device-1 and copy the new file.
“Today's limit of 200 questions …”The daily AI limit per device. It resets at 09:00 JST; change dailyLimitPerDevice in settings.json and redeploy to raise it.
ask fails on localOllama is not running. Start it with ollama serve or brew services start ollama.
The local adapter cannot open the portClose the Serial Monitor; only one program can use the port.
Bedrock refuses the modelSubmit the one-time use-case form for Anthropic models in the AWS console.

7Clean up and cost

A deployed backend that is not called costs almost nothing. An AI question cost about USD 0.00017 in our evaluation (Claude Haiku 4.5 at USD 1.10 and 5.50 per million input and output tokens, Japan inference profile in Tokyo, 2026-10-12); counting faces costs USD 1.30 per 1,000 images in Tokyo. npm run stats shows calls, time, and the estimated cost.

cd backend
npm run stats
npm run destroy        # removes everything from your account, data included
