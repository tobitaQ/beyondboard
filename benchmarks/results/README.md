**環境**
- ボード：ESP32 Dev Module（ESP32、2 コア 240MHz、520KB SRAM）

- Wi-Fi：2.4GHz、チャンネル 11（近くに同じ・隣のチャンネルの Wi-Fi あり）

## 1. 遅延（ESP32 の実機、各 30 回、ms）

p95 は nearest rank（並べた ceil(0.95n) 番目、30 個なら 29 番目）。2026-10-26 に lower nearest rank（28 番目）から替えた。

| 操作 | aws 中央値 | aws p95 | aws 最大 | local 中央値 | local p95 | local 最大 |
|---|---|---|---|---|---|---|
| begin | 2,014 | — | — | 20 | — | — |
| save | 67 | 1,498 | 10,498 | 25 | 26 | 27 |
| load | 107 | 208 | 209 | 28 | 30 | 30 |
| run | 207 | 308 | 498 | 42 | 50 | 63 |
| ask（選択肢あり） | 618 | 727 | 1,838 | 121 | 134 | 2,094 |

- aws の save の p95・最大は、2.4GHz の Wi-Fi の混雑による再送と考えられる。同じ時刻のサーバーでの処理は 9〜25ms で、遅れは ESP32 からサーバーに届くまでの間に起きていた（`diag-reuse.csv` の 100 回の再計測では、最大は最初の接続の 498ms、p95 は 177ms）。
- local の ask の最大は、Ollama がモデルを読み込む最初の 1 回。
- ファイル：`latency-aws-warm.csv`、`latency-local-serial.csv`、`diag-reuse.csv`

## 4. サイズ（bytes、`sizes.csv`）

| ボード | 比較 | flash の増分 | 静的 RAM の増分 |
|---|---|---|---|
| ESP32 | 手書きの HTTPS → aws | +10,504 | +220 |
| ESP32 | シリアルだけ → local | +9,540 | +180 |
| ESP32-S3 | 手書きの HTTPS → aws | +10,280 | +320 |
| ESP32-S2 | 手書きの HTTPS → aws | +10,776 | +320 |
| ESP32-C3 | 手書きの HTTPS → aws | +11,370 | +312 |
| ESP32-C6 | 手書きの HTTPS → aws | +11,430 | +312 |
| Arduino UNO | シリアルだけ → local | +9,562（32KB 中） | +162（2KB 中。文字列を `F()` でフラッシュに移す前は +780） |

- 手書きの HTTPS は、Wi-Fi・証明書の確認・1 回の POST だけで、エラー処理も契約もない最小のもの。
- UNO では、文字列をフラッシュに移したことで RAM の増分が 780B → 162B になった。flash の増分は約 9.6KB（32KB の約 30%）。
- ESP32 の実機での空きヒープの最小値：aws で約 170KB。
- 上の表の aws の行は、本物の `aws_config.h` を使って計測したときの値。2026-10-02 から `sizes.sh` は、秘密の情報を使わないように偽の値の `aws_config.h` でビルドする。その場合、aws のスケッチは flash が約 1.8KB 小さくなり（同じコードで比べて）、現在の `sizes.csv` の増分は ESP32 +9,404 / +428、S3 +9,176 / +320、S2 +9,664 / +320、C3 +10,348 / +312、C6 +10,408 / +312 になる。aws を使わない行（UNO、local、手書きの HTTPS など）は以前と同じ値になる。
- 現在のコードでの local の増分（ESP32、シリアルだけ → local）は +9,800 / +180（上の表の +9,540 は 2026-10-01 のコミット 9fde647 の時点の値で、その後に機能を足した）。

### 5 つのサンプルアプリの大きさ（ESP32、flash、bytes、`sizes.csv` の `arduino_cloud/`・`ours/`・`raw_aws/` の行）

| アプリ | Arduino Cloud | 本研究（aws） | 手書きの MQTT（生の AWS） |
|---|---|---|---|
| 1 保存 | 1,102,031 | 1,036,019 | 999,647 |
| 2 設定の読み込み | 1,100,539 | 1,034,831 | 1,005,835 |
| 3 異常検知 | 1,124,743 | 1,035,135 | 1,007,031 |
| 4 AI | 1,134,191 | 1,034,763 | 1,007,551 |
| 5 AI + 保存 | 1,136,775 | 1,036,451 | 1,007,767 |
| 平均 | 1,119,656 | 1,035,440 | 1,005,566 |

- 2026-10-14 に測り直した（著者が `benchmarks/sizes.sh` を実行）。Arduino Cloud のアプリ 3〜5 は、Webhook の形からボードが HTTPS で直接呼ぶ形に変えたので、HTTPClient と ArduinoJson の分だけ大きくなった（前の平均は 1,103,290）。本研究の値は 64〜68 バイト増えた（ライブラリの小さな変更）
- 静的 RAM：Arduino Cloud 48,704〜49,700、本研究 47,596、手書きの MQTT 46,112〜46,220。
- ライブラリ：ArduinoIoTCloud 2.10.0（依存するライブラリも含む）、MQTT 2.5.3（Joel Gaehwiler）、ArduinoJson 7.4.3。本研究の値は偽の `aws_config.h` でのもの。
- local だけのスケッチの大きさ：aws を別のヘッダーに分ける前（コミット 53e3f46 の前）は `06_LocalAll` が 1,033,655 bytes、分けた後は 288,827 bytes（1,033KB → 289KB）。現在は 291,031 bytes。

## 5. 料金

- ask の 1 回あたりの実際の料金は約 USD 0.00017（構築のときの目安は USD 0.0014 で、多めの見積もり）。2026-10-28 に著者が `npm run stats -- 30` で測った：直近 30 日で ask 238 回（失敗 4）、AI のトークン 28,153 in・1,910 out、単価は ap-northeast-1 の日本の推論プロファイル（Regional）の USD 1.10・5.50（AWS の価格表 API、2026-10-12 版）で計 USD 0.0415、238 回で割って 0.000174（成功 234 回なら 0.000177）。1 問の平均は入力約 118・出力約 8 トークン。以前の値 0.00015 は Global の単価（USD 1・5）で別の期間に計算したもの（今回の記録を旧単価で計算すると 0.00016）。
- save / load / run は 1 回 USD 0.000003 程度（Lambda と DynamoDB）。
